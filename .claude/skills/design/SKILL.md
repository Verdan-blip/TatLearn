# «Дизайн» в проекте Тамыр

## Определение

Слово **«дизайн»** в запросах пользователя всегда означает файлы из каталога `design/` в корне проекта, а не Figma и не что-то внешнее:

| Путь | Что это |
|---|---|
| `design/Tatar App Screens.dc.html` | Источник истины для UI: 15 экранов 390×844 на одном холсте (HTML, сгенерирован Claude Design) |
| `design/support.js` | Скрипт поддержки холста `.dc.html`, подключается самим макетом. Не менять без необходимости |
| `design/screens/NN.png` | Эталонные рендеры экранов (Playwright + системный Chrome) |
| `design/icons/*` | Логотипы сторонних сервисов (Google, VK) для кнопок входа; те же файлы лежат в `composeResources/drawable` |
| `design/mascot/*.svg`, `design/mascot-prompt.md` | Исходники и бриф маскота Мырауҗан |
| `design/OFL-PTSans.txt` | Лицензия шрифта PT Sans |

Если пользователь говорит «в дизайне нет X», надо искать X именно здесь, а не спрашивать, о каком дизайне речь.

## Работа с макетом

- `.dc.html` — обычный текстовый HTML со стилями прямо в атрибутах. Редактируется стандартными инструментами (Read/Edit), отдельный инструмент не нужен.
- Токены макета (цвета, радиусы, отступы) должны совпадать с `TamyrTheme` в `core/designsystem`. Новые значения сначала добавляются как токены, потом используются.
- **После правки HTML эталонные PNG устаревают.** Их нужно перерендерить (Playwright + системный Chrome) и сказать об этом пользователю; нельзя оставлять PNG, не соответствующий HTML.
- Чего нет в макете — это `// TODO(design)` в коде (например, тост, состояния ошибок полей, логотипы провайдеров). Если пользователь просит «нарисовать», это значит добавить элемент в `design/Tatar App Screens.dc.html`, затем обновить PNG и только потом реализовывать в Compose.
- Не проверено, как правки руками в HTML будут вести себя при повторном открытии файла в самом Claude Design. Перед крупными правками стоит сделать коммит, чтобы можно было откатить.
