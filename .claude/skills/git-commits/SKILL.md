# Коммиты в проекте Тамыр

## Правило

Каждое законченное атомарное изменение коммитится сразу, без вопроса «закоммитить?» ни перед коммитом, ни в конце ответа. Пользователь заранее разрешил такие коммиты (подтверждено повторно 25.10.2026). Не жди, пока он попросит: сделал, проверил, закоммитил и сообщи хеш и заголовок в отчёте. Не коммить:
- код, который не собирается или ломает тесты (сначала проверка из `CLAUDE.md`: `./gradlew :androidApp:assembleDebug :shared:linkDebugFrameworkIosSimulatorArm64`, для логики ещё тесты);
- незаконченную работу и эксперименты: их оставляй в рабочем дереве и скажи об этом.

`git push`, создание веток, `--amend`, `reset` и любые переписывания истории по-прежнему только по прямой просьбе.

## Стиль сообщения

- Одна строка: краткое описание сделанного на английском языке.
- Повелительное наклонение, с заглавной буквы, без точки в конце, примерно до 70 символов: `Add TamyrToast for unavailable social login`, `Fix social login mode`, `Update auth docs`.
- Тело коммита не нужно, если это не требуется для понимания. Тег-префиксов (`feat:`, `fix:`) нет.
- В конце сообщения остаётся строка соавторства, которую задаёт среда (Co-Authored-By).

## Как делить на коммиты

- Один коммит — одно логическое изменение: макет, компонент, фича, документация, скиллы лучше раздельно, если их можно описать одной короткой строкой каждый.
- Если изменения тесно связаны (код, его тесты и документация), они идут одним коммитом.
- Перед коммитом смотри `git status` и `git diff --stat`, добавляй файлы явно по именам, а не `git add -A`, чтобы случайно не захватить лишнее.
