# feature/intro

Знакомство в гостевом режиме: имя и цвет аватара. Спека: `.docs/19-intro.md`, макеты `design/screens/25.png`, `28.png`, `29.png`.

## Поток
`IntroScene` -> `IntroContent` <- `IntroViewModel(ProfileRepository)`. «Продолжить» и «Пропустить» сохраняют профиль и ведут на главную (стек заменяется). Показывается из онбординга и при запуске, если онбординг уже показан, а профиля нет (`StartDestinationResolver`).

## Решения (25.10.2026, business-analyst, ux-designer, владелец)
- Собираем только имя и цвет аватара; цель изучения и ежедневная цель отложены (ничего не меняют в продукте). Возраст, город, фото, e-mail не собираем.
- Знакомство можно пропустить; пустое имя не ошибка (сохраняется «Друг»), «Продолжить» блокируется только при имени длиннее 20 символов.
- После знакомства главная. Уже вошедшим пользователям профиль создаётся из имени сессии, знакомство им не показывается.
- «Готово» на клавиатуре только закрывает её, а не уходит вперёд (замечание владельца: цвет ещё не выбран); вперёд только «Продолжить». Тап по свободному месту закрывает клавиатуру.
- Позы Мыраужана на знакомстве не предлагаем, чтобы экран оставался коротким; они в профиле.
- При открытой клавиатуре маскот и подпись прячутся (`WindowInsets.ime`), кнопки над клавиатурой (`imePadding`).

## Фича-флаг
`BuildConfig.REGISTRATION_ENABLED` (`tamyr.registrationEnabled`). Флаг включён: поток без знакомства (Onboarding -> Auth).
